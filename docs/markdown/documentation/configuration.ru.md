# :material-file-cog-outline: Конфигурация

[Конфигурационный файл](concepts/config-file.md) описывает весь ваш бот: Telegram
соединение, кто может его использовать, меню [кнопок](concepts/button.md) и
журналирование. Вы передаете его с помощью `--config` командам, которые его
читают — `run`, `validate`, `fmt` и `list-functions` (см. [CLI](cli.md)).

Все ключи используют `lower_snake_case`. **Неизвестные ключи отклонены**,
поэтому опечатка – это ошибка. Вы увидите эту ошибку сразу же, когда вы
[validate](cli.md#validate).

**Обязательное** означает, что проверка не удалась, если поле отсутствует или
пусто после применения значений по умолчанию. **Необязательные** поля можно
опустить; в столбце «По умолчанию» показано, какое значение будет использовано.

Впервые в проекте? Начните с [Запуск в CLI](installation/download-and-run.md),
который описывает создание первой конфигурации. См.
[Концепции](concepts/config-file.md) для словаря, используемого ниже.

## :material-rocket-launch-outline: Минимальная конфигурация { #a-minimal-config }

Только `telegram` (с токеном и одним [разрешенным
пользователем](concepts/allowed-users.md)) и `menu` обязательны. Все остальное
имеет значение по умолчанию:

!!! example "Начните с одного разрешенного пользователя и одной кнопки"

    ```yaml title="config.yaml (minimal)"
    telegram:
      bot_token: "YOUR_BOT_TOKEN"
      allowed_users:
        - "123456789"

    menu:
      - name: Uptime
        type: button
        function: command
        command: "uptime"
    ```

Папка `config-examples/` в релизе включает как минимальную, так и полный пример.

## :material-card-bulleted-outline: Корневые поля { #root-fields }

| Поле | Тип | Требуется | По умолчанию | Описание |
|-------|------|----------|---------|-------------|
| `telegram` | объект | да | — | Настройки Telegram (см. ниже) |
| `menu` | список | да | — | Дерево меню; хотя бы один узел |
| `function_directory` | строка | нет | не установлен | Каталог YAML с пользовательскими функциями (см. правила ниже) |
| `shell` | строка | нет | `/bin/bash` | [Оболочка](concepts/shell.md) используется как `shell -c "<command>"` |
| `timeout` | продолжительность | нет | `60s` | Тайм-аут команды по умолчанию |
| `max_output_bytes` | целое число | нет | `524288` | Максимальный вывод, сохраняемый для каждой команды (см. [Сколько вывода команды вы видите](#how-much-command-output-you-see)) |
| `workdir` | строка | нет | текущий каталог процесса | Рабочий каталог по умолчанию для команд |
| `env` | объект | нет | пустой | Дополнительные переменные среды для команд |
| `menu_columns` | целое число | нет | `2` | Кнопки элементов в каждой строке под окном сообщения |
| `page_size` | целое число | нет | `8` | Элементов на странице до нумерации страниц |
| `confirm_ttl` | продолжительность | нет | `5m` | Как долго приглашение [confirmation](concepts/confirmation.md) остается действительным |
| `enable_run_command` | логическое значение | нет | `false` | Покажите кнопку **`$ >_ Run Command`**, которая запускает следующее сообщение как команду оболочки. По умолчанию выключено. Любой, кто может использовать бота, сможет затем выполнить любую команду на хосте, поэтому включайте это только в том случае, если вы доверяете каждому разрешенному пользователю. Помещение этого ключа в `telegram` недействительно. |
| `logging` | объект | нет | встроенный журнал по умолчанию | Именованные журналы (см. ниже) |

??? note "Что, если я пропущу `shell`?"

    Его можно не указывать. Бот использует `/bin/bash`. То же самое для
    `timeout`, `page_size`, и другие необязательные корневые поля: опустите их,
    и будут применяться значения по умолчанию. Вам нужно только чтобы установить
    их, если вам нужно значение, отличное от значения по умолчанию (например,
    `shell: /bin/sh`).

### Сколько выводимых команд вы видите { #how-much-command-output-you-see }

Применяются два ограничения, одно за другим. `max_output_bytes` — это **ваш**
предел и выходит за пределы ограничения Telegram, которое вы не можете изменить.

**1. Ваш лимит: `max_output_bytes`** (по умолчанию `524288`, т. е. 512 КБ).

Пока команда выполняется, бот сохраняет не более этой части вывода, отдельно для
нормального вывода и вывода ошибок. Лишний вывод отбрасывается, но сама команда
продолжает выполняться до тех пор, пока не завершится или не достигнет
`timeout`. В этом случае результат начинается с `(output truncated)`.

**2. Ограничение Telegram: одно сообщение содержит не более 4096 байт**

Это ограничение задано Telegram. Если результат длиннее одного сообщения, бот
разбивает его на несколько сообщений. Каждая часть отправляется в качестве
ответа на предыдущую часть, поэтому они остаются вместе и в порядке, и
появляются кнопки меню в последней части. Разделение происходит по границам
строк, когда это возможно, поэтому линии не разрезаются пополам.

Если после разделения результат все еще очень длинный, бот останавливается через
10 сообщений, а последнее заканчивается примечанием типа `(output too long;
showing first N bytes)`, где `N` — сколько выходных данных вы действительно
получили.

Таким образом, поднятие `max_output_bytes` позволяет боту сохранять больше
выходных данных, но вы все равно видите максимум около десяти таких сообщений.
Для вывода такой длины обычно лучше сократить саму команду (например `journalctl
-u nginx | tail -n 50`) или записать полный вывод в файл на сервере.

### `function_directory` правила { #function_directory-rules }

| Ситуация | Результат |
|-----------|--------|
| Ключ отсутствует | Информационный журнал; только встроенные функции |
| Ключ присутствует, но пуст (`""`) | Информационный журнал; только встроенные функции |
| Ключ установлен на путь, который не существует или недоступен | Критическая ошибка; процесс останавливается |
| Путь существует, но каталог пуст | ОК |

!!! warning "Неверный путь останавливает бота"

    Если `function_directory` указывает на папку, которая не существует или не
    может быть прочитать, программа останавливается с ошибкой вместо того, чтобы
    запуститься без вашего пользовательские функции.

## :material-send-circle-outline: `telegram` { #telegram }

| Поле | Тип | Требуется | По умолчанию | Описание |
|-------|------|----------|---------|-------------|
| `bot_token` | строка | да | — | Токен бота от BotFather |
| `allowed_users` | список строк | да | — | [Разрешенные пользователи](concepts/allowed-users.md) |
| `api` | строка | нет | `https://api.telegram.org` | Базовый URL-адрес API бота |
| `proxy.enabled` | логическое значение | нет | `false` | Использовать прокси для Telegram API |
| `proxy.url` | строка | условный | — | Требуется, если `proxy.enabled` — `true` |
| `insecure` | логическое значение | нет | `false` | Пропустить проверку TLS (не рекомендуется) |

Неавторизованные пользователи получают сообщение со своими `user_id` и
`username`, чтобы они могли запросить доступ у администратора. Точно так же вы
сможете найти свой собственный идентификатор в первый раз — см. [Запуск в CLI →
Шаг 5](installation/download-and-run.md#step-5-find-your-user-id-if-needed).

!!! example "Подключиться через прокси"

    ```yaml title="telegram section with a proxy"
    telegram:
      bot_token: "123456789:AAExampleTokenValue"
      allowed_users:
        - "123456789"        # числовой id пользователя
        - "@alice"           # или имя пользователя
      proxy:
        enabled: true
        url: "socks5://127.0.0.1:10808"
    ```

Чтобы разрешенные пользователи могли вводить команды оболочки из Telegram,
установите это в **корне** файла (не в `telegram`):

!!! tip "Добавьте одну корневую настройку"

    ```yaml title="Enable the Run Command button"
    enable_run_command: true
    ```

## :material-menu: Меню { #menu }

Этот раздел является справочником по полю. Подробное объяснение с примерами см.
[Меню](concepts/menu.md). Каждая [кнопка](concepts/button.md) или
[узел категории](concepts/category.md):

| Поле | Тип | Требуется | Описание |
|-------|------|----------|-------------|
| `name` | строка | да | Отображаемое имя (уникальное среди соседних элементов без учёта регистра) |
| `type` | `category` \| `button` | да | Тип узла |
| `items` | список | да, если `category` | Дочерние элементы; категория должна иметь хотя бы один |
| `function` | строка | да, если `button` | [Имя функции](concepts/function.md) |
| `command` | строка | да, если `function: command` | Команда оболочки для встроенного `command` |
| `path` | строка | да, если `function: script` | Путь к скрипту для встроенного `script` |
| `icon` | строка | нет | Дополнительный префикс эмодзи |
| `id` | строка | нет | Необязательный идентификатор для этого узла. Его можно не указывать |
| `confirm` | логическое значение | нет | Запросите [подтверждение ](concepts/confirmation.md) перед запуском (по умолчанию `false`) |
| `timeout` | продолжительность | нет | Переопределить глобальный тайм-аут |
| `workdir` | строка | нет | Переопределить рабочий каталог |
| `env` | объект | нет | Дополнительные переменные окружения для этой кнопки |
| `columns` | целое число | нет | Переопределить столбцы для этой категории |
| `args` | строка | нет | Необязательные аргументы для `script` |
| Любое объявленное имя параметра | скаляр | как объявлено функцией | Значение, передаваемое выбранной функции, например `url`, `host`, `unit` или `lines` |

Для **кнопки** любой другой скалярный ключ рассматривается как параметр функции.
Его имя должно соответствовать параметру, объявленному выбранной функцией.
Неизвестные имена параметров не проходят [`validate`](cli.md#validate).
Значения, объявленные как `int` или `bool` также проверяются. Строки, числа и
логические значения можно записывать напрямую как значения YAML; числа не
нуждаются в кавычках.

В **категории** любой ключ за пределами полей категории выше является ошибкой.
Категории не запускают функции, поэтому у них не может быть ключей параметров.

`command`, `path` и `args` — поля ярлыков, которые заполняют параметры те же
имена. Другие имена [parameter](concepts/parameter.md) записываются напрямую на
кнопке. Не размещайте значения кнопок внутри вложенной карты `params:`. См.
[Функции → Передача значений из кнопки](functions/index.md#passing-values-from-a-button).

## :material-math-log: `logging` { #logging }

Необязательно. Если этот параметр опущен, используется консольный журнал по
умолчанию на `stderr` по адресу `info`.

Именованные журналы:

!!! example "Запись обычных журналов и файла аудита"

    ```yaml title="logging section with an audit file"
    logging:
      logs:
        default:
          level: info
          format: console   # или JSON
          output:
            - output: stderr
        audit:
          level: info
          format: json
          output:
            - output: file
              file: /var/log/telegram-commander/audit.log
    ```

Поддерживаемые места вывода: `stdout`, `stderr`, `file`, `discard`.

Показанный выше журнал `audit` записывает каждую запущенную команду (кто, какая
кнопка, код выхода, продолжительность). См. [Журнал аудита
](concepts/audit-log.md).
