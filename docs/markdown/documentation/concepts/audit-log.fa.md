# :material-history: گزارش حسابرسی

جریان گزارشی جداگانه که هر فرمان اجراشده را ثبت می‌کند: چه کسی آن را اجرا
کرده، کدام [دکمه](button.md) استفاده شده، کد خروج چه بوده و اجرا چقدر طول
کشیده است. این گزارش زیر `logging` در [فایل پیکربندی](config-file.md)
تنظیم می‌شود.

وقتی بعداً می‌خواهید بدانید چه کسی ساعت سه صبح سرویسی را راه‌اندازی مجدد
کرده یا آیا دکمهٔ پشتیبان‌گیری دیشب واقعاً کارش را تمام کرده، این سابقه را
بررسی می‌کنید. چون جریان مستقلی دارد، پس از حذف دوره‌ای گزارش عادی برنامه
نیز می‌توانید آن را نگه دارید.

هر اجرا یک خط اضافه می‌کند و این خط‌ها در مجموع به چهار پرسش پاسخ می‌دهند:

| پرسش | اطلاعاتی که خط به شما می‌دهد |
|---|---|
| چه کسی؟ | حساب تلگرامی که دکمه را لمس کرده است |
| چه کاری؟ | دکمه‌ای که استفاده کرده است |
| موفق بود؟ | کد خروجی که فرمان برگردانده است |
| چقدر طول کشید؟ | مدت‌زمانی که اجرای فرمان طول کشیده است |

!!! example "نوشتن گزارش حسابرسی در فایل خودش"

    ```yaml title="logging section of config.yaml"
    logging:
      logs:
        audit:
          level: info
          format: json
          output:
            - output: file
              file: /var/log/telegram-commander/audit.log
    ```
