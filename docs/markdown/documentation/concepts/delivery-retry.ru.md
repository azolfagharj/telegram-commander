# :material-refresh: Повторные попытки доставки

Если соединение с Telegram обрывается на мгновение, пока бот отправляет
результат, сообщение не теряется. Бот сам пробует ещё раз, каждый раз ожидая
немного дольше, пока отправка не удастся.

Когда сам Telegram просит бота притормозить, бот ждёт ровно столько, сколько
просит Telegram, а не угадывает собственную паузу.

Сообщения в один и тот же чат всё равно приходят в том порядке, в котором вы
их вызвали, даже если вы нажимаете несколько кнопок, пока соединение
испытывает проблемы.

Если сбой длится слишком долго, бот в конце концов перестаёт пытаться для
этого результата. В чате ничего не появляется, и ничего не остаётся
наполовину отправленным — попытка отмечается только в журнале сервера, вам
она никогда не показывается.

!!! tip "Для обычной настройки ничего задавать не нужно"

    Значения по умолчанию сами справляются с коротким сбоем сети. Измените,
    как долго бот продолжает попытки, с помощью `delivery_retry_backoff`,
    `delivery_retry_backoff_max` и `delivery_retry_ttl` в вашем
    [конфигурационном файле](config-file.md).
